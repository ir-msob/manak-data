# رهنمودهای هوش مصنوعی مسئولانه (Responsible AI Guidelines)

**نام پلتفرم:** Enterprise AI Context & Automation Platform

**نسخه:** 1.1

**وضعیت:** پیش‌نویس بازبینی‌شده

**سند مرجع نام‌گذاری:** `Naming_And_Terminology_Glossary`

---

## ۱. هدف سند

این سند با هدف تعریف چارچوب حاکمیت و اخلاق هوش مصنوعی برای طراحی، توسعه، استقرار و بهره‌برداری از قابلیت‌های مبتنی بر هوش مصنوعی در پلتفرم تدوین شده است. هدف آن تضمین استفاده مسئولانه، شفاف، قابل اعتماد و منطبق با قوانین، مقررات و ارزش‌های سازمان از هوش مصنوعی است.

این سند به‌عنوان مرجع اصلی برای تمام تیم‌های محصول، توسعه، معماری، امنیت، حاکمیت داده و هوش مصنوعی در زمینه طراحی و پیاده‌سازی قابلیت‌های هوش مصنوعی به‌صورت اخلاقی و مسئولانه عمل می‌کند.

---

## ۲. دامنه سند

این سند تمام قابلیت‌های مبتنی بر هوش مصنوعی در پلتفرم را پوشش می‌دهد:

| حوزه | نمونه‌ها |
| :--- | :--- |
| **مدل‌های زبانی بزرگ (Large Language Models — LLM)** | مدل‌های مورد استفاده برای تولید پاسخ، تحلیل، استدلال و تصمیم‌گیری |
| **مدل‌های نمایش عددی و بازمرتب‌سازی (Embedding & Reranking Models)** | مدل‌های مورد استفاده برای جستجوی معنایی و بازیابی اطلاعات |
| **Agentهای هوشمند (Intelligent Agents)** | Agentهای تک‌وظیفه و چندوظیفه که با مدل‌ها و Toolها تعامل دارند |
| **موتورهای تصمیم‌یار (Decision Support Engines)** | قابلیت‌های تصمیم‌گیری خودکار مبتنی بر هوش مصنوعی |
| **تولید با بازیابی افزایش‌یافته (RAG) و بازیابی دانش** | فرآیندهای بازیابی و تولید پاسخ مبتنی بر دانش سازمانی |
| **ابزارهای متصل به هوش مصنوعی (AI‑connected Tools)** | Toolهایی که توسط Agentها برای اجرای عملیات فراخوانی می‌شوند |
| **داده‌های مورد استفاده** | داده‌های ورودی، Context، حافظه و دانشی که به مدل‌ها ارائه می‌شود |
| **خروجی‌های تولیدشده** | پاسخ‌ها، تصمیم‌ها، پیشنهادات و اقدامات تولیدشده توسط هوش مصنوعی |

## ۳. اهداف

| هدف | توضیح |
| :--- | :--- |
| **استفاده مسئولانه از هوش مصنوعی** | اطمینان از اینکه هوش مصنوعی در راستای منافع کاربران، سازمان و جامعه به‌کار گرفته می‌شود |
| **افزایش اعتماد کاربران** | ایجاد شفافیت و قابلیت توضیح‌پذیری برای افزایش اعتماد کاربران به خروجی‌های هوش مصنوعی |
| **کاهش ریسک‌های اخلاقی و قانونی** | شناسایی و مدیریت ریسک‌های مرتبط با سوگیری، تبعیض، نشت داده و رفتارهای نادرست مدل |
| **ایجاد فرآیندهای نظارت بر مدل‌ها** | تعریف فرآیندهای پایش، ارزیابی و بازنگری مدل‌ها در طول چرخه عمر |
| **تعریف مسئولیت‌های سازمانی** | شفاف‌سازی نقش‌ها و مسئولیت‌های افراد و تیم‌ها در قبال هوش مصنوعی |

## ۴. اصول بنیادین

| اصل | توضیح |
| :--- | :--- |
| **عدالت (Fairness)** | مدل‌ها نباید باعث تبعیض ناعادلانه بر اساس ویژگی‌هایی مانند نژاد، جنسیت، سن، مذهب یا وضعیت اجتماعی شوند. داده‌ها، خروجی‌ها و تصمیم‌ها باید به‌صورت مستمر از نظر سوگیری (Bias) ارزیابی و اصلاح شوند. |
| **شفافیت (Transparency)** | کاربران باید بدانند که پاسخ‌ها چگونه تولید شده‌اند، از چه منابعی استفاده شده است، مدل مورد استفاده کدام است و محدودیت‌ها و عدم قطعیت‌های سیستم چیست. |
| **قابلیت تبیین (Explainability)** | در صورت امکان، سیستم باید دلایل تصمیم یا پاسخ را به زبان قابل فهم برای کاربر ارائه کند. کاربر باید بتواند منطق پشت هر پاسخ یا اقدام را درک کند. |
| **پاسخگویی (Accountability)** | مسئولیت نهایی تمامی تصمیم‌های مهم بر عهده انسان است و نه مدل هوش مصنوعی. انسان‌ها باید بتوانند تصمیمات هوش مصنوعی را بازبینی، تأیید یا رد کنند. |
| **قابلیت اعتماد (Trustworthiness)** | سامانه باید قابل پیش‌بینی، پایدار، ایمن، قابل ممیزی و مقاوم در برابر خطا و حملات باشد. کاربران باید بتوانند به خروجی‌های سیستم اعتماد کنند. |
| **حفظ حریم خصوصی (Privacy)** | اطلاعات شخصی و حساس تنها مطابق با سیاست‌های سازمان و قوانین مربوطه جمع‌آوری، پردازش و نگهداری می‌شوند. داده‌های شخصی نباید بدون رضایت و هدف مشخص استفاده شوند. |
| **امنیت (Security)** | مدل‌ها، داده‌ها و Agentها باید در برابر سوءاستفاده، حملات (مانند تزریق دستور، آلودگی داده، شکستن محدودیت‌ها) و نشت اطلاعات محافظت شوند. |

## ۶. چرخه عمر مدل هوش مصنوعی

هر مدل هوش مصنوعی مورد استفاده در پلتفرم، از مراحل زیر عبور می‌کند و برای هر مرحله کنترل‌های مشخصی تعریف می‌شود:

| مرحله | توضیح | کنترل‌ها |
| :--- | :--- | :--- |
| **انتخاب مسئله (Problem Selection)** | تعیین کاربرد و هدف مدل در پلتفرم | ارزیابی ضرورت، بررسی گزینه‌های غیرAI، تحلیل ریسک |
| **جمع‌آوری داده (Data Collection)** | تهیه داده‌های مورد نیاز برای آموزش یا ارزیابی | اطمینان از مجوز داده، رعایت حریم خصوصی، تنوع داده |
| **آماده‌سازی داده (Data Preparation)** | پالایش، نرمال‌سازی و آماده‌سازی داده | حذف سوگیری‌ها، ناشناس‌سازی، اعتبارسنجی کیفیت |
| **آموزش یا انتخاب مدل (Training/Selection)** | آموزش مدل جدید یا انتخاب مدل موجود | ارزیابی عملکرد، بررسی سوگیری، مقایسه گزینه‌ها |
| **اعتبارسنجی (Validation)** | آزمون مدل در محیط کنترل‌شده | آزمون عملکرد، امنیت، سوگیری، کیفیت پاسخ |
| **استقرار (Deployment)** | قرار دادن مدل در محیط تولید | استقرار تدریجی، پایش اولیه، قابلیت بازگشت |
| **پایش (Monitoring)** | نظارت مستمر بر عملکرد مدل در تولید | پایش کیفیت، خطا، سوگیری، مصرف منابع |
| **بازآموزی یا بازنشستگی (Retraining/Retirement)** | به‌روزرسانی یا حذف مدل | ارزیابی نیاز به بازآموزی، برنامه‌ریزی جایگزینی، حذف امن |

---

## ۷. اعتبارسنجی مدل (Model Validation)

پیش از استقرار هر مدل در محیط تولید، اعتبارسنجی در حوزه‌های زیر الزامی است:

| حوزه | معیارهای ارزیابی |
| :--- | :--- |
| **دقت (Accuracy)** | صحت پاسخ‌ها در سناریوهای مختلف، مقایسه با خط پایه (Baseline) |
| **پایداری (Robustness)** | رفتار مدل در برابر ورودی‌های غیرمنتظره، مرزی و مخرب |
| **سوگیری (Bias)** | بررسی تبعیض بر اساس ویژگی‌های جمعیتی، جنسیتی، زبانی و فرهنگی |
| **کیفیت پاسخ (Response Quality)** | مرتبط بودن، کامل بودن، مفید بودن و قابل فهم بودن پاسخ‌ها |
| **امنیت (Security)** | مقاومت در برابر تزریق دستور، شکستن محدودیت‌ها و حملات مشابه |
| **عملکرد (Performance)** | زمان پاسخ، توان عملیاتی، مصرف منابع در بارهای مختلف |
| **مصرف منابع (Resource Consumption)** | مصرف Token، CPU، حافظه و هزینه هر درخواست |

---

## ۸. مدیریت ریسک (Risk Management)

ریسک‌های مرتبط با هوش مصنوعی باید شناسایی، ارزیابی و مدیریت شوند:

| ریسک | توضیح | راهکارهای پیشگیری و واکنش |
| :--- | :--- | :--- |
| **توهم (Hallucination)** | تولید اطلاعات نادرست یا ساختگی با اطمینان بالا | استفاده از RAG با منابع معتبر، اعتبارسنجی خروجی، نمایش سطح اطمینان |
| **سوگیری و تبعیض (Bias & Discrimination)** | تولید پاسخ‌های تبعیض‌آمیز بر اساس ویژگی‌های جمعیتی | ارزیابی دوره‌ای سوگیری، تنوع در داده‌های Context، بازخورد کاربران |
| **نشت داده (Data Leakage)** | افشای اطلاعات حساس در خروجی مدل | پنهان‌سازی داده‌های حساس، کنترل دسترسی، بررسی خروجی |
| **وابستگی بیش از حد (Over-reliance)** | کاربران بدون بررسی، به خروجی مدل اعتماد می‌کنند | نمایش محدودیت‌ها، تشویق به بازبینی، حضور انسان در حلقه برای موارد حساس |
| **تزریق دستور (Prompt Injection)** | تزریق دستورات مخرب به ورودی مدل | اعتبارسنجی ورودی، جداسازی دستورات کاربر از Context، محافظ (Guardrail) |
| **آلودگی داده (Data Poisoning)** | آلوده‌سازی داده‌های بازیابی‌شده با اطلاعات نادرست | اعتبارسنجی منبع داده، مکانیزم بازخورد، امتیاز اطمینان (Confidence Score) |
| **شکستن محدودیت‌ها (Jailbreak)** | دور زدن محدودیت‌های امنیتی مدل | استفاده از محافظ‌های پیشرفته، پایش الگوهای مشکوک، به‌روزرسانی مدل |

---

## ۹. حضور انسان در چرخه تصمیم (Human-in-the-Loop)

در تصمیم‌های مهم و پرریسک، حضور انسان در چرخه تصمیم‌گیری الزامی است:

| حوزه | الزام Human-in-the-Loop |
| :--- | :--- |
| **تصمیمات مالی** | تأیید انسانی برای تراکنش‌های مالی، سرمایه‌گذاری، بودجه‌بندی |
| **تصمیمات حقوقی** | تأیید انسانی برای قراردادها، تعهدات قانونی، انطباق |
| **تصمیمات امنیتی** | تأیید انسانی برای تغییر دسترسی‌ها، عملیات حساس امنیتی |
| **تصمیمات منابع انسانی** | تأیید انسانی برای استخدام، ارتقاء، اخراج، ارزیابی عملکرد |
| **عملیات پرریسک** | تأیید انسانی برای حذف داده، تغییر زیرساخت، عملیات برگشت‌ناپذیر |

**پیاده‌سازی:** Human-in-the-Loop از طریق مکانیزم‌های زیر پیاده‌سازی می‌شود:
- درخواست تأیید قبل از اجرای Toolهای پرریسک (تعریف‌شده در سند `Integration_Boundaries_And_Tooling_Framework`)
- نمایش پیشنهادات و دلایل به کاربر و انتظار برای تأیید
- ثبت کامل تصمیمات و اقدامات برای ممیزی

## ۱۰. استفاده مسئولانه از داده (Responsible Data Usage)

| اصل | پیاده‌سازی |
| :--- | :--- |
| **استفاده از داده‌های مجاز** | فقط داده‌هایی استفاده می‌شوند که مجوز استفاده برای اهداف مشخص را داشته باشند |
| **رعایت حقوق مالکیت داده** | احترام به حقوق مالکیت فکری و قراردادهای استفاده از داده |
| **حداقل‌سازی داده (Data Minimization)** | فقط داده‌های ضروری برای انجام Task به مدل ارسال می‌شوند |
| **ناشناس‌سازی (Anonymization)** | در صورت نیاز، داده‌های شخصی قبل از استفاده ناشناس می‌شوند |
| **رعایت سیاست‌های حاکمیت داده** | انطباق کامل با سیاست‌های تعریف‌شده در سند `Data_Governance_and_Compliance` |

## ۱۱. مدیریت پرامپت (Prompt Management)

پرامپت‌ها به‌عنوان بخش حیاتی تعامل با مدل، باید با دقت مدیریت شوند:

| الزام | توضیح |
| :--- | :--- |
| **نسخه‌بندی (Versioning)** | هر پرامپت باید نسخه‌بندی شده و تغییرات آن قابل رهگیری باشد |
| **بازبینی (Review)** | پرامپت‌ها باید توسط تیم فنی و در صورت نیاز توسط تیم محصول بازبینی شوند |
| **عدم قرار دادن اطلاعات محرمانه** | اطلاعات حساس (مانند رمز عبور، کلیدها، اطلاعات شخصی قابل شناسایی) نباید در پرامپت‌ها قرار گیرند |
| **ثبت و ممیزی (Logging & Audit)** | پرامپت‌های مهم (به‌ویژه در موارد حساس) باید ثبت و قابل ممیزی باشند |
| **جداسازی دستورات سیستم و کاربر** | دستورات سیستمی (System Instructions) باید از ورودی کاربر جدا شوند تا از تزریق دستور جلوگیری شود |
| **آزمایش و بهینه‌سازی** | پرامپت‌ها باید به‌صورت دوره‌ای آزمایش و بهینه‌سازی شوند تا کیفیت پاسخ بهبود یابد |

---

## ۱۲. نظارت بر مدل‌ها (Model Monitoring)

به‌صورت مستمر، شاخص‌های زیر برای هر مدل در حال تولید پایش می‌شوند:

| شاخص | توضیح |
| :--- | :--- |
| **کیفیت پاسخ (Response Quality)** | ارزیابی دوره‌ای کیفیت پاسخ‌ها از نظر دقت، مرتبط بودن و مفید بودن |
| **نرخ خطا (Error Rate)** | درصد درخواست‌هایی که با خطا مواجه می‌شوند |
| **نرخ توهم (Hallucination Rate)** | درصد پاسخ‌هایی که حاوی اطلاعات نادرست یا ساختگی هستند |
| **نرخ سوگیری (Bias Rate)** | شناسایی الگوهای تبعیض‌آمیز در پاسخ‌ها |
| **میزان استفاده (Usage Rate)** | تعداد درخواست‌ها، Token مصرفی و هزینه هر مدل |
| **تغییر رفتار مدل (Drift)** | تغییرات در کیفیت و رفتار مدل در طول زمان که نیاز به بررسی دارد |
| **بازخورد کاربران (User Feedback)** | امتیازات و نظرات کاربران درباره کیفیت پاسخ‌ها |

**اقدامات در صورت مشاهده انحراف:**
- اعلام هشدار به تیم فنی و کمیته حاکمیت هوش مصنوعی
- بررسی علت و انجام اقدام اصلاحی
- در صورت لزوم، بازگشت به نسخه پایدار یا تعویض مدل

---

## ۱۳. ممیزی و ثبت (Audit & Logging)

تمام تصمیم‌های مهم هوش مصنوعی باید قابل رهگیری باشند و اطلاعات زیر ثبت شوند:

| فیلد | توضیح |
| :--- | :--- |
| **مدل استفاده‌شده (Model Used)** | نام، ارائه‌دهنده و نسخه مدل |
| **نسخه مدل (Model Version)** | شناسه دقیق نسخه مدل |
| **پرامپت (Prompt)** | ورودی ارسال‌شده به مدل (با رعایت امنیت و پنهان‌سازی) |
| **زمینه (Context)** | دانش و Context ارسال‌شده به مدل |
| **ابزارهای اجراشده (Tools Executed)** | فهرست Toolهای فراخوانی‌شده و نتایج آن‌ها |
| **نتیجه (Result)** | خروجی مدل، تصمیم یا اقدام انجام‌شده |
| **زمان اجرا (Execution Time)** | زمان شروع و پایان پردازش |
| **کاربر درخواست‌کننده (Requesting User)** | شناسه کاربر یا سرویس درخواست‌دهنده |
| **هزینه (Cost)** | هزینه تخمینی پردازش |

**دوره نگهداری:** لاگ‌های مرتبط با هوش مصنوعی حداقل به مدت ۱ سال برای اهداف ممیزی و تحلیل نگهداری می‌شوند.

## ۱۴. انطباق با استانداردها و قوانین (Compliance)

معماری پلتفرم باید امکان انطباق با چارچوب‌ها و استانداردهای زیر را فراهم کند:

| استاندارد/چارچوب | حوزه | الزامات کلیدی مرتبط |
| :--- | :--- | :--- |
| **EU AI Act** | قانون هوش مصنوعی اتحادیه اروپا | طبقه‌بندی ریسک، شفافیت، حاکمیت داده، نظارت انسانی |
| **GDPR** | مقررات عمومی حفاظت از داده | حق توضیح، شفافیت، حریم خصوصی، حداقل‌سازی داده |
| **ISO/IEC 42001** | سیستم مدیریت هوش مصنوعی | حاکمیت، مدیریت ریسک، پایش، بهبود مستمر |
| **NIST AI RMF** | چارچوب مدیریت ریسک هوش مصنوعی | شناسایی ریسک، اندازه‌گیری، مدیریت، حاکمیت |
| **OECD AI Principles** | اصول هوش مصنوعی OECD | رشد فراگیر، حقوق بشر، شفافیت، پاسخگویی |

**مسئولیت انطباق:** تیم حاکمیت هوش مصنوعی به همراه تیم حقوقی و تیم امنیت مسئول ارزیابی دوره‌ای انطباق و رفع شکاف‌های شناسایی‌شده هستند.

| :--- | :--- | :--- |

این سند مرجع اصلی طراحی، توسعه، استقرار و بهره‌برداری مسئولانه از قابلیت‌های هوش مصنوعی در پلتفرم است. رعایت اصول و کنترل‌های تعریف‌شده در این سند، اعتماد کاربران را افزایش می‌دهد، ریسک‌های قانونی و اخلاقی را کاهش می‌دهد و پایداری بلندمدت قابلیت‌های هوش مصنوعی پلتفرم را تضمین می‌کند.

**ثبات سند:** این سند باید با تغییرات در قوانین، استانداردها، فناوری‌های هوش مصنوعی و نیازهای کسب‌وکار هم‌گام باشد. هر تغییر در قابلیت‌های هوش مصنوعی پلتفرم باید از منظر Responsible AI بررسی شده و در صورت نیاز این سند به‌روزرسانی شود.
