# فهرست قوانین کسب‌وکار (Business Rule Catalog)

**نام پلتفرم:** Enterprise AI Context & Automation Platform

**نسخه:** 1.0

**وضعیت:** پیش‌نویس

**سند مرجع نام‌گذاری:** `Naming_And_Terminology_Glossary`

---

## ۱. هدف سند

این سند با هدف جمع‌آوری، دسته‌بندی و مستندسازی **همه قوانین مهم کسب‌وکاری** (Business Rules) پلتفرم تدوین شده است. قوانین کسب‌وکار، عبارات شرطی، محدودیت‌ها، سنجه‌های اعتبارسنجی و شرایط فعال‌سازی هستند که رفتار سیستم را در مواجهه با سناریوهای مختلف تعیین می‌کنند. این قوانین اغلب به‌صورت «اگر-آن‌گاه» (If-Then) یا معادلات منطقی بیان می‌شوند و پیاده‌سازی صحیح آن‌ها برای تضمین عملکرد درست، امن و منطبق با انتظارات کسب‌وکار سیستم حیاتی است.

این سند به‌عنوان مرجع اصلی برای تیم‌های توسعه، معماری، محصول و حاکمیت داده در زمینه درک، پیاده‌سازی و مدیریت قوانین کسب‌وکار عمل می‌کند و تضمین می‌کند که منطق حیاتی و موارد خاص حوزه با درک دقیق توسط توسعه‌دهندگان پیاده‌سازی شود.

---

## ۲. دامنه سند

این سند تمام قوانین کسب‌وکاری را که بر رفتار پلتفرم تأثیر می‌گذارند، پوشش می‌دهد و شامل موارد زیر است:

- **قوانین امنیت و دسترسی:** احراز هویت، مجوزدهی، کنترل دسترسی
- **قوانین حاکمیت داده:** طبقه‌بندی داده، دوره نگهداری، کیفیت داده
- **قوانین مدیریت دانش:** اعتبارسنجی، نمایه‌سازی، بازیابی
- **قوانین حافظه و تجربه:** ذخیره‌سازی، بازه نگهداری، دسترسی
- **قوانین ابزارها و اقدامات:** مجوز اجرا، تأیید انسانی، محدودیت‌ها
- **قوانین عامل‌ها و هماهنگی:** تصمیم‌گیری، اولویت‌بندی، Fallback
- **قوانین هوش مصنوعی مسئولانه:** سوگیری، شفافیت، Human-in-the-Loop
- **قوانین عملیاتی:** مقیاس‌پذیری، پایش، هشداردهی

قوانین فنی سطح پایین (مانند محدودیت‌های شبکه، تنظیمات JVM، یا قوانین کدنویسی) در این سند ثبت نمی‌شوند و باید در اسناد فنی مربوطه مستند شوند.

## ۳. اصول مدیریت قوانین کسب‌وکار

| اصل | توضیح |
| :--- | :--- |
| **مرکزیت (Centralization)** | قوانین کسب‌وکار باید در یک مکان مرکزی (این سند) مستند شوند تا از پراکندگی و تناقض جلوگیری شود. |
| **قابل رهگیری (Traceability)** | هر قانون باید دارای شناسه یکتا، تاریخ ایجاد، وضعیت و مسئول مشخص باشد تا تغییرات آن قابل رهگیری باشد. |
| **قابل آزمون (Testability)** | هر قانون باید به‌گونه‌ای بیان شود که قابلیت نوشتن آزمون‌های خودکار برای آن وجود داشته باشد. |
| **جداسازی از پیاده‌سازی (Separation from Implementation)** | قوانین کسب‌وکار باید مستقل از جزئیات پیاده‌سازی فنی تعریف شوند تا امکان تغییر آن‌ها بدون تغییر در کد فراهم باشد. |
| **اولویت‌بندی (Prioritization)** | قوانین بر اساس اولویت (بحرانی، بالا، متوسط، پایین) دسته‌بندی می‌شوند تا تیم‌ها بدانند کدام قوانین نیاز به پیاده‌سازی فوری دارند. |
| **بازبینی دوره‌ای (Periodic Review)** | قوانین باید به‌صورت دوره‌ای (حداقل سالانه) بازبینی شوند تا با تغییرات نیازمندی‌های کسب‌وکار هم‌گام بمانند. |

## ۴. ساختار ثبت قانون

هر قانون کسب‌وکار با استفاده از ساختار زیر ثبت می‌شود:

| فیلد | توضیح | الزامی |
| :--- | :--- | :--- |
| **شناسه قانون (Rule ID)** | شناسه یکتا برای ارجاع به قانون (مثلاً BR‑XXX) | بله |
| **عنوان (Title)** | نام کوتاه و گویا که اصل قانون را بیان کند | بله |
| **دسته‌بندی (Category)** | دسته‌بندی قانون (امنیت، داده، دانش، حافظه، ابزار، عامل، هوش مصنوعی، عملیاتی) | بله |
| **دامنه‌های مرتبط (Related Domains)** | دامنه‌هایی که این قانون در آن‌ها اعمال می‌شود | بله |
| **شرح (Description)** | شرح کامل قانون و دلیل وجود آن | بله |
| **بیان منطقی (Logical Expression)** | بیان قانون به‌صورت «اگر-آن‌گاه» یا معادله منطقی | بله |
| **اولویت (Priority)** | سطح اولویت (بحرانی، بالا، متوسط، پایین) | بله |
| **وضعیت (Status)** | وضعیت قانون (پیش‌نویس، تأییدشده، پیاده‌سازی‌شده، منسوخ) | بله |
| **مسئول (Owner)** | تیم یا شخص مسئول پیاده‌سازی و نگهداری قانون | بله |
| **تاریخ ایجاد (Created Date)** | تاریخ ثبت قانون | بله |
| **تاریخ آخرین بازبینی (Last Reviewed)** | تاریخ آخرین بازبینی قانون | خیر |
