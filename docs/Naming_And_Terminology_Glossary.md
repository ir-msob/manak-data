# واژه‌نامه و استاندارد نام‌گذاری (Naming & Terminology Standard)

**نام پلتفرم:** Enterprise AI Context & Automation Platform

**نسخه:** 1.2

**وضعیت:** پیش‌نویس بازبینی‌شده

---

## ۱. هدف سند

این سند به‌عنوان **مرجع واحد نام‌گذاری و واژه‌نامه اصطلاحات** برای کل پلتفرم تدوین شده است. تمام تیم‌های محصول، معماری، توسعه و مستندسازی باید برای نام‌گذاری کامپوننت‌ها و استفاده از اصطلاحات کلیدی به این سند مراجعه کنند. هدف، ایجاد زبانی مشترک و یکدست در تمام لایه‌های پلتفرم و جلوگیری از ابهام و پراکندگی نام‌هاست.

---

## ۲. نام‌گذاری استاندارد کامپوننت‌های اصلی

| نام استاندارد (Canonical Name) | معادل فارسی | مسئولیت خلاصه |
| :--- | :--- | :--- |
| **Interface & Integration Layer** | لایه تعامل و یکپارچه‌سازی | نقطه ورود استاندارد تمام درخواست‌ها (API، Event، SDK، Webhook) |
| **Agent Orchestration Engine** | موتور هماهنگی و ارکستراسیون Agent | تحلیل Intent، Planning، مدیریت اجرای Agent، مسیریابی |
| **Knowledge & Context Engine** | موتور دانش و Context | Ingestion، پردازش، Indexing، Retrieval، Context Assembly |
| **Model Management Engine** | موتور مدیریت مدل | Registry، انتخاب مدل، مدیریت Provider، Routing |
| **Action & Tool Engine** | موتور اجرای عملیات و ابزار | Tool Registry، اجرای Tool/Workflow، Sandbox، Reliability |
| **Memory Management Engine** | موتور مدیریت حافظه | Session Memory، Long-Term Memory، Episodic Memory، Experience |
| **Governance & Platform Services** | سرویس‌های حاکمیت و پلتفرم | Security، Policy، Guardrail، Audit، Monitoring، Cost Control |

> این نام‌ها، نام‌های رسمی و معیار پلتفرم هستند. نام‌های قبلی یا معادل‌های دیگر (مانند Reasoning & Orchestration Layer یا Action Engine) صرفاً به‌عنوان نام مستعار (Alias) قابل قبول‌اند، اما نباید به‌عنوان عنوان رسمی در مستندات جدید استفاده شوند.

## ۳. واژه‌نامه اصطلاحات کلیدی (Terminology Glossary)

### مفاهیم هوش مصنوعی

| اصطلاح | توضیح فارسی |
| :--- | :--- |
| **Context** | مجموعه اطلاعات مرتبطی که پیش از پاسخ‌گویی یا تصمیم‌گیری در اختیار مدل هوش مصنوعی قرار می‌گیرد. |
| **Intent** | هدف واقعی کاربر یا سیستم از یک درخواست، که باید پیش از برنامه‌ریزی اجرا تشخیص داده شود. |
| **Agent** | واحد اجرایی هوشمند که با استفاده از مدل، Context و Toolها یک Task را دنبال و اجرا می‌کند. |
| **Prompt** | ورودی متنی که به مدل ارسال می‌شود تا پاسخ یا عملیات مورد نظر را تولید کند. |
| **System Prompt** | دستورالعمل سطح‌بالایی که رفتار کلی مدل را در طول مکالمه هدایت می‌کند. |
| **Prompt Template** | الگوی از پیش تعریف‌شده برای ساخت Prompt که شامل متغیرها و دستورالعمل‌های ثابت است. |
| **Prompt Injection** | حمله‌ای که در آن ورودی مخرب سعی می‌کند رفتار مورد انتظار مدل را دستکاری کند. |
| **Guardrail** | مجموعه کنترل‌هایی که از تولید یا اجرای خروجی نامناسب یا ناامن توسط مدل جلوگیری می‌کند. |
| **RAG (Retrieval-Augmented Generation)** | روشی که در آن مدل پیش از پاسخ، اطلاعات مرتبط را از منابع دانش بازیابی و به Context اضافه می‌کند. |
| **Hallucination** | تولید محتوایی توسط مدل که صحیح نیست یا به داده‌های آموزشی پشتیبانی نمی‌شود. |
| **Token** | واحد پایه پردازش در مدل‌های زبانی (معادل کلمه یا بخشی از کلمه) که برای محاسبه هزینه و محدودیت طول ورودی استفاده می‌شود. |
| **Fine-Tuning** | فرایند تنظیم مجدد یک مدل از پیش‌آموزش‌دیده بر روی داده‌های خاص برای بهبود عملکرد در حوزه‌ای مشخص. |

### مفاهیم معماری و یکپارچه‌سازی

| اصطلاح | توضیح فارسی |
| :--- | :--- |
| **Connector** | مؤلفه‌ای که ارتباط پلتفرم با یک منبع داده یا سیستم خارجی مشخص را برقرار می‌کند. |
| **Adapter** | لایه‌ای که رابط داخلی پلتفرم را به رابط یک Provider یا سیستم خارجی تبدیل می‌کند. |
| **Event-Driven Architecture** | سبک معماری که در آن ارتباط بین Componentها از طریق رویداد (Event) و به‌صورت غیرهمزمان انجام می‌شود. |
| **Loose Coupling** | طراحی‌ای که در آن Componentها کمترین وابستگی مستقیم به یکدیگر را دارند. |
| **Workflow** | دنباله‌ای از گام‌های از پیش تعریف‌شده که برای انجام یک Task مشخص اجرا می‌شوند. |
| **Pipeline** | زنجیره‌ای از پردازش‌های متوالی که داده یا درخواست را از مرحله‌ای به مرحله‌ی بعد هدایت می‌کند. |
| **Idempotency** | ویژگی یک عملیات که تکرار آن، نتیجه یکسانی با اجرای یک‌باره تولید می‌کند؛ برای Retry ایمن ضروری است. |
| **Sandbox** | محیط اجرای ایزوله که ریسک اجرای عملیات ناشناخته یا پرریسک را محدود می‌کند. |
| **Resilience** | قابلیت سیستم برای بازیابی از خطاها و ادامه عملکرد صحیح در شرایط نامطلوب. |
| **Circuit Breaker** | الگویی که در صورت تکرار خطا در یک سرویس، درخواست‌ها را به‌طور موقت قطع می‌کند تا از فشار بیشتر جلوگیری شود. |
| **Retry Policy** | سیاستی که تعداد دفعات و فاصله‌ی زمانی تکرار یک عملیات ناموفق را تعیین می‌کند. |

### مفاهیم امنیت و حاکمیت

| اصطلاح | توضیح فارسی |
| :--- | :--- |
| **Zero Trust** | اصل امنیتی که بر اساس آن هیچ کاربر، سرویس یا Agentی به‌طور پیش‌فرض قابل اعتماد نیست. |
| **RBAC (Role-Based Access Control)** | کنترل دسترسی بر اساس نقش سازمانی کاربر. |
| **ABAC (Attribute-Based Access Control)** | کنترل دسترسی بر اساس ویژگی‌هایی مانند واحد سازمانی، حساسیت داده یا Context درخواست. |
| **Least Privilege** | اصل طراحی که بر اساس آن هر Component یا کاربر فقط به حداقل منابع لازم برای انجام کار خود دسترسی دارد. |
| **Human-in-the-Loop** | فرآیندی که در آن تأیید انسانی پیش از اجرای عملیات حساس الزامی است. |
| **Audit Trail** | ثبت کامل و قابل‌ردیابی رویدادها، تصمیم‌ها و عملیات برای اهداف امنیتی و انطباق. |
| **Data Encryption** | رمزنگاری داده‌ها در حالت ذخیره‌سازی (At Rest) و در حال انتقال (In Transit) برای محافظت در برابر دسترسی غیرمجاز. |
| **Secrets Management** | مدیریت امن کلیدها، رمزهای عبور و توکن‌ها با استفاده از سرویس‌های اختصاصی مانند Vault. |
| **Observability** | قابلیت اندازه‌گیری وضعیت داخلی سیستم از طریق متریک‌ها، لاگ‌ها و Tracing. |
| **Telemetry** | جمع‌آوری خودکار داده‌های عملکرد و رفتار سیستم برای نظارت و عیب‌یابی. |

### مفاهیم داده و دانش

| اصطلاح | توضیح فارسی |
| :--- | :--- |
| **Chunking** | تقسیم اسناد بزرگ به بخش‌های کوچک‌تر برای پردازش و بازیابی مؤثرتر. |
| **Embedding** | نمایش عددی (Vector) از یک متن یا داده که برای جستجوی معنایی استفاده می‌شود. |
| **Semantic Search** | جستجوی مبتنی بر معنای محتوا به‌جای تطابق دقیق کلمات. |
| **Vector Database** | پایگاه داده تخصصی برای ذخیره و جستجوی Embeddingها. |
| **Knowledge Graph** | ساختار داده‌ای که موجودیت‌ها و روابط بین آن‌ها را برای بازیابی دقیق‌تر دانش نگهداری می‌کند. |
| **Ingestion** | فرایند وارد کردن، پالایش و آماده‌سازی داده‌ها از منابع مختلف برای ذخیره‌سازی و بازیابی. |
| **Indexing** | ایجاد ساختار جستجوپذیر (مانند شاخص‌های برداری) بر روی داده‌های ذخیره‌شده برای افزایش سرعت Retrieval. |

## ۴. ارجاعات

- برای جزئیات پیاده‌سازی مؤلفه‌های نام‌برده، به سند **معماری مؤلفه‌ها** مراجعه کنید.
- برای قوانین نگارش و قالب‌بندی مستندات، به سند **راهنمای سبک مستندسازی** مراجعه کنید.
- برای فرایند به‌روزرسانی این واژه‌نامه، به سند **فرایند مدیریت تغییر** مراجعه کنید.
