# معماری دامنه مدیریت جریان کار (Workflow Domain Architecture)

**نام پلتفرم:** Enterprise AI Context & Automation Platform

**نسخه:** 1.0

**وضعیت:** پیش‌نویس

**سند مرجع نام‌گذاری:** `Naming_And_Terminology_Glossary`

---

## ۱. هدف سند

این سند با هدف تعریف معماری دامنه **مدیریت جریان کار** (Workflow Domain) تدوین شده است. این دامنه مسئول مدیریت فرآیندهای چندمرحله‌ای و گردش‌کارهای سازمانی (Business Workflows) است که شامل توالی‌های از پیش تعریف‌شده از گام‌ها، تصمیم‌گیری‌های شرطی، اجرای موازی، انتظار برای رویدادها و تعامل با انسان‌ها (Human‑in‑the‑Loop) می‌شود. هدف آن ایجاد بستری استاندارد، انعطاف‌پذیر، مقیاس‌پذیر و قابل اعتماد برای تعریف، اجرا، پایش و مدیریت گردش‌کارهای پیچیده سازمانی است.

این سند به‌عنوان مرجع اصلی برای تیم‌های توسعه، معماری، محصول و عملیات در زمینه طراحی و پیاده‌سازی زیرساخت گردش‌کارهای سازمانی پلتفرم عمل می‌کند.

---

## ۲. دامنه سند

این سند تمام جنبه‌های مرتبط با دامنه مدیریت جریان کار را پوشش می‌دهد و شامل موارد زیر است:

- **Workflow Definition:** تعریف و ثبت گردش‌کارها با استفاده از زبان‌های استاندارد (BPMN، DSL، JSON)
- **Workflow Engine:** موتور اجرای گردش‌کارها با پشتیبانی از اجرای ترتیبی، موازی، شرطی و مبتنی بر رویداد
- **State Manager:** مدیریت وضعیت هر گردش‌کار و گام‌های آن در طول اجرا
- **Task Management:** مدیریت وظایف (Task) درون هر گردش‌کار شامل ایجاد، تخصیص، اجرا و تکمیل
- **Human‑in‑the‑Loop:** مدیریت گام‌هایی که نیاز به تأیید، ورودی یا تصمیم‌گیری انسانی دارند
- **Workflow Orchestration:** هماهنگی با عامل‌ها و ابزارها برای اجرای گام‌ها
- **Error Handling & Recovery:** مدیریت خطا، Retry، Rollback و اقدامات جبرانی در گردش‌کارهای چندمرحله‌ای
- **Workflow Monitoring & Observability:** پایش وضعیت، پیشرفت و سلامت گردش‌کارها
- **Workflow Versioning:** نسخه‌بندی گردش‌کارها برای مدیریت تغییرات و سازگاری با گردش‌کارهای در حال اجرا
- **Workflow Templates:** قالب‌های از پیش تعریف‌شده برای گردش‌کارهای رایج سازمانی
- **Workflow Instance Management:** ایجاد، مدیریت و پایش نمونه‌های اجرای گردش‌کار (Workflow Instance)
- **Workflow Trigger Management:** مدیریت روش‌های آغاز گردش‌کار شامل API، رویداد، زمان‌بندی، Webhook و اجرای دستی
- **Workflow Scheduling:** زمان‌بندی اجرای گردش‌کارها و پشتیبانی از اجرای دوره‌ای (Cron)
- **Workflow Validation:** اعتبارسنجی تعریف گردش‌کار قبل از انتشار و اجرا
- 
جزئیات پیاده‌سازی فنی و کدنویسی در اسناد سطح پایین‌تر تدوین می‌شوند. این سند صرفاً **معماری سطح بالا و اصول طراحی** دامنه را تعریف می‌کند.

## ۳. اصول طراحی دامنه

| اصل | توضیح |
| :--- | :--- |
| **انعطاف‌پذیری (Flexibility)** | گردش‌کارها باید به‌صورت پویا و با استفاده از زبان‌های استاندارد (BPMN، DSL) تعریف شوند و امکان تغییر در زمان اجرا (Runtime) را داشته باشند. |
| **قابلیت رهگیری (Traceability)** | تمام گام‌های هر گردش‌کار، تغییرات وضعیت، تصمیمات و نتایج باید ثبت و قابل ردیابی باشند تا ممیزی و تحلیل امکان‌پذیر باشد. |
| **مقاومت در برابر خطا (Fault Tolerance)** | گردش‌کارها باید در برابر خطاهای گام‌ها، قطعی سرویس‌ها و Timeout مقاوم باشند و با مکانیزم‌های Retry، Rollback و Compensation مدیریت شوند. |
| **مدیریت وضعیت (State Management)** | وضعیت هر گردش‌کار و گام‌های آن باید به‌صورت پایدار (Persistent) ذخیره شود تا در صورت خرابی سیستم، گردش‌کار از همان نقطه ادامه یابد. |
| **هماهنگی با عامل‌ها و ابزارها** | گردش‌کارها باید بتوانند گام‌های خود را به عامل‌های هوشمند یا ابزارهای اجرایی واگذار کنند و نتایج را دریافت کنند. |
| **حضور انسان در حلقه (Human‑in‑the‑Loop)** | گردش‌کارها باید از گام‌هایی پشتیبانی کنند که نیاز به تأیید، ورودی یا تصمیم‌گیری انسانی دارند و مکانیزم انتظار و Timeout برای آن‌ها تعریف شود. |
| **نسخه‌بندی (Versioning)** | گردش‌کارها باید نسخه‌بندی شوند تا تغییرات در تعریف گردش‌کار، گردش‌کارهای در حال اجرا را مختل نکند. تعریف پایه Semantic Versioning در سند `Versioning_And_Compatibility_Strategy` آمده است. |
| **مقیاس‌پذیری (Scalability)** | موتور گردش‌کار باید توانایی مدیریت هزاران گردش‌کار همزمان با گام‌های متعدد را داشته باشد. |
| **عدم اجرای تکراری (Idempotency)** | اجرای مجدد یک درخواست، پیام یا رویداد نباید باعث اجرای چندباره یک گام یا ایجاد داده تکراری شود. |
| **جداسازی مستأجران (Multi-Tenancy Isolation)** | تمام داده‌ها، وضعیت‌ها، رویدادها و منابع هر مستأجر باید به‌صورت کامل از سایر مستأجران ایزوله باشند. |

## ۴. مؤلفه‌های اصلی دامنه

### ۴.۱. Workflow Definition (تعریف گردش‌کار)

**مسئولیت:** تعریف و ثبت گردش‌کارها با استفاده از زبان‌های استاندارد و قابل فهم برای انسان و ماشین.

**وظایف کلیدی:**

- **ثبت گردش‌کار:** ثبت گردش‌کار جدید با فراداده کامل (نام، توضیحات، نسخه، مالک)
- **تعریف گام‌ها (Steps):** تعریف گام‌های گردش‌کار شامل نوع (Task، Decision، Parallel، Wait، Human)
- **تعریف وابستگی‌ها:** تعیین وابستگی‌های بین گام‌ها (ترتیبی، موازی، شرطی)
- **تعریف شرط‌ها (Conditions):** تعریف شرایط تصمیم‌گیری و انشعاب در گردش‌کار
- **تعریف ورودی/خروجی:** تعیین داده‌های ورودی به هر گام و خروجی مورد انتظار
- **تعریف خطا و Compensation:** تعریف رفتار در صورت خطا و اقدامات جبرانی

**زبان‌های تعریف گردش‌کار:**

| زبان | توضیح | کاربرد |
| :--- | :--- | :--- |
| **BPMN 2.0** | استاندارد جهانی برای مدل‌سازی فرآیندهای کسب‌وکار | گردش‌کارهای پیچیده سازمانی |
| **DSL (Domain Specific Language)** | زبان اختصاصی دامنه مبتنی بر JSON/YAML | گردش‌کارهای ساده تا متوسط |
| **Workflow DSL** | زبان اختصاصی پلتفرم برای تعریف گردش‌کارها | گردش‌کارهایی که با عامل‌ها و ابزارها تعامل دارند |
| **State Machine** | مدل مبتنی بر ماشین حالت برای گردش‌کارهای با حالت محدود | گردش‌کارهای ساده و قابل پیش‌بینی |

**نمونه تعریف گردش‌کار به‌صورت DSL:**

```json
{
  "workflow_id": "wf-123",
  "name": "تأیید و انتشار مستندات",
  "version": "1.0",
  "steps": [
    {
      "id": "step-1",
      "type": "task",
      "name": "بارگذاری سند",
      "action": "document_upload",
      "next": "step-2"
    },
    {
      "id": "step-2",
      "type": "human",
      "name": "تأیید محتوا توسط مدیر",
      "assignee": "manager",
      "timeout": "24h",
      "next_condition": {
        "approved": "step-3",
        "rejected": "step-4"
      }
    },
    {
      "id": "step-3",
      "type": "task",
      "name": "انتشار سند",
      "action": "document_publish",
      "next": "step-5"
    },
    {
      "id": "step-4",
      "type": "task",
      "name": "ارسال بازخورد به نویسنده",
      "action": "send_feedback",
      "next": "step-5"
    },
    {
      "id": "step-5",
      "type": "end",
      "name": "پایان گردش‌کار"
    }
  ]
}
```

#### ۴.۱.۱. Workflow Instance (نمونه اجرای گردش‌کار)

**مسئولیت:** ایجاد و مدیریت نمونه‌های اجرای گردش‌کار بر اساس یک تعریف (Workflow Definition).

**وظایف کلیدی:**

- ایجاد نمونه جدید از گردش‌کار
- نگهداری وضعیت اجرای هر نمونه
- ارتباط هر نمونه با نسخه مشخصی از تعریف گردش‌کار
- مدیریت متغیرها و داده‌های اختصاصی هر نمونه
- مدیریت شناسه کسب‌وکاری (Business Key) برای رهگیری فرآیندهای سازمانی

---

### ۴.۲. Workflow Engine (موتور گردش‌کار)

**مسئولیت:** اجرای گردش‌کارها، مدیریت گام‌ها، وضعیت‌ها و هماهنگی با سایر سرویس‌ها.

**وظایف کلیدی:**

- **شروع گردش‌کار:** راه‌اندازی یک نمونه جدید از گردش‌کار با داده‌های ورودی
- **مدیریت گام‌ها:** اجرای گام‌ها بر اساس ترتیب، شرایط و وابستگی‌ها
- **انشعاب و شرط:** مدیریت انشعاب‌ها و تصمیم‌گیری‌های شرطی در گردش‌کار
- **اجرای موازی:** اجرای گام‌های مستقل به‌صورت هم‌زمان
- **انتظار و Timeout:** مدیریت گام‌های انتظار (برای رویداد یا تأیید انسانی) و Timeout
- **هماهنگی با عامل‌ها:** ارسال درخواست به عامل‌ها برای اجرای گام‌های هوشمند
- **هماهنگی با ابزارها:** فراخوانی ابزارها برای اجرای گام‌های عملیاتی
- **مدیریت خطا:** مدیریت خطاهای گام‌ها با Retry، Rollback و اقدامات جبرانی
- **اجرای Sub Workflow:** اجرای گردش‌کارهای دیگر به‌عنوان بخشی از یک گردش‌کار بزرگ‌تر
- **Correlation رویدادها:** تطبیق رویدادهای دریافتی با نمونه صحیح گردش‌کار بر اساس شناسه‌های کسب‌وکاری
- **اجرای Idempotent:** جلوگیری از اجرای مجدد گام‌ها در صورت دریافت درخواست یا رویداد تکراری

---

### ۴.۳. State Manager (مدیر وضعیت)

**مسئولیت:** مدیریت پایدار و قابل اعتماد وضعیت هر گردش‌کار و گام‌های آن.

**وظایف کلیدی:**

- **ذخیره‌سازی وضعیت:** ذخیره وضعیت جاری هر گردش‌کار (Running, Paused, Completed, Failed)
- **ذخیره‌سازی گام‌ها:** ذخیره وضعیت هر گام (Pending, In Progress, Completed, Failed, Skipped)
- **ذخیره‌سازی داده‌های میانی:** ذخیره داده‌های تولیدشده در هر گام برای استفاده در گام‌های بعدی
- **بازیابی وضعیت:** بازیابی وضعیت گردش‌کار در صورت خرابی سیستم برای ادامه از همان نقطه
- **مدیریت تاریخچه:** نگهداری تاریخچه کامل تغییرات وضعیت برای ممیزی و تحلیل
- **مدیریت قفل:** جلوگیری از اجرای هم‌زمان یک گردش‌کار توسط چندین نمونه

**فیلدهای کلیدی وضعیت گردش‌کار:**

| فیلد                          | توضیح |
|:------------------------------| :--- |
| `workflow_instance_id`        | شناسه یکتای نمونه گردش‌کار |
| `workflow_definition_id`      | شناسه تعریف گردش‌کار |
| `version`                     | نسخه تعریف گردش‌کار |
| `status`                      | وضعیت (Running, Paused, Completed, Failed, Canceled) |
| `current_step_id`             | شناسه گام فعلی |
| `steps`                       | لیست گام‌ها با وضعیت و داده‌های هرکدام |
| `variables`                   | متغیرهای سراسری گردش‌کار |
| `started_at`                  | زمان شروع |
| `completed_at`                | زمان پایان |
| `updated_at`                  | زمان آخرین به‌روزرسانی |
| `tenant_id`                   | شناسه مستأجر |
| `created_by`                  | کاربر یا سیستم شروع‌کننده |
| `business_key`                | شناسه کسب‌وکاری جهت تطبیق رویدادها و رهگیری فرآیند   |
| `correlation_id`              | شناسه ارتباط بین درخواست‌ها، رویدادها و عملیات مرتبط |
| `parent_workflow_instance_id` | شناسه گردش‌کار والد در صورت اجرای Sub Workflow       |

### ۴.۴. Task Management (مدیریت وظایف)

**مسئولیت:** مدیریت وظایف (Task) درون هر گردش‌کار شامل ایجاد، تخصیص، اجرا و تکمیل.

**وظایف کلیدی:**

- **ایجاد Task:** ایجاد Task برای هر گام گردش‌کار
- **تخصیص Task:** تخصیص Task به انسان (User) یا عامل (Agent)
- **مدیریت اولویت:** تعیین اولویت Task‌ها برای اجرا
- **مدیریت وضعیت:** Track وضعیت Task (Open, Assigned, In Progress, Completed, Canceled)
- **مدیریت زمان‌بندی:** تعیین زمان‌بندی اجرا یا مهلت انجام
- **یکپارچگی با عامل‌ها:** ارسال Task به عامل‌های هوشمند برای اجرا
- **یکپارچگی با انسان:** ارائه Task به کاربران از طریق رابط کاربری برای تأیید یا ورودی

**انواع Task:**

| نوع Task              | توضیح | مجری |
|:----------------------| :--- | :--- |
| **Automated Task**    | گامی که به‌طور کامل خودکار توسط سیستم اجرا می‌شود | سیستم / ابزار |
| **Agent Task**        | گامی که به یک عامل هوشمند واگذار می‌شود | عامل هوشمند |
| **Human Task**        | گامی که نیاز به اقدام، تأیید یا ورودی انسانی دارد | کاربر |
| **Integration Task**  | گامی که یکپارچه‌سازی با سیستم خارجی را انجام می‌دهد | ابزار / API |
| **Wait Task**         | گامی که برای وقوع یک رویداد یا شرط منتظر می‌ماند | سیستم |
| **Sub Workflow Task** | اجرای یک گردش‌کار دیگر به‌عنوان بخشی از گردش‌کار جاری | موتور گردش‌کار |
| **Script Task**       | اجرای منطق یا اسکریپت داخلی                           | سیستم          |
| **Timer Task**        | انتظار تا زمان مشخص یا اجرای زمان‌بندی‌شده            | سیستم          |

### ۴.۵. Human‑in‑the‑Loop (حضور انسان در حلقه)

**مسئولیت:** مدیریت گام‌هایی که نیاز به تأیید، ورودی یا تصمیم‌گیری انسانی دارند.

**وظایف کلیدی:**

- **ارسال درخواست به کاربر:** ارسال درخواست تأیید، ورودی یا تصمیم‌گیری به کاربر از طریق رابط کاربری
- **انتظار برای پاسخ:** انتظار برای پاسخ کاربر با امکان Timeout
- **مدیریت Timeout:** در صورت عدم پاسخ کاربر در زمان مشخص، اقدام جایگزین (Escalate، Cancel، Auto‑Approve)
- **ثبت تصمیم:** ثبت تصمیم انسانی برای ممیزی و یادگیری
- **اعمال تصمیم:** اعمال تصمیم کاربر بر روی گردش‌کار (ادامه، اصلاح، لغو)

**سناریوهای Human‑in‑the‑Loop:**

| سناریو | توضیح | مثال |
| :--- | :--- | :--- |
| **Approval** | تأیید یا رد یک گام توسط مدیر | تأیید مستندات، تأیید تغییرات |
| **Information Input** | وارد کردن اطلاعات توسط کاربر | تکمیل فرم، ارائه توضیحات |
| **Decision Making** | تصمیم‌گیری بین چند گزینه توسط کاربر | انتخاب مسیر گردش‌کار، انتخاب رویکرد |
| **Error Escalation** | ارجاع خطا یا استثنا به انسان برای تصمیم‌گیری | خطای غیرقابل‌بازیابی، وضعیت غیرمنتظره |

---

#### ۴.۵.۱. Workflow Trigger Management (مدیریت آغاز گردش‌کار)

**مسئولیت:** مدیریت تمامی روش‌های آغاز اجرای گردش‌کار.

**وظایف کلیدی:**

- آغاز از طریق API
- آغاز از طریق رویداد (Event)
- آغاز زمان‌بندی‌شده (Scheduler)
- آغاز از طریق Webhook
- آغاز دستی توسط کاربر
- آغاز توسط سایر گردش‌کارها

---

### ۴.۶. Error Handling & Recovery (مدیریت خطا و بازیابی)

**مسئولیت:** مدیریت خطاها در گردش‌کارهای چندمرحله‌ای با مکانیزم‌های Retry، Rollback و Compensation.

**وظایف کلیدی:**

- **تشخیص خطا:** شناسایی خطا در هر گام گردش‌کار
- **Retry:** تلاش مجدد با Exponential Backoff برای خطاهای موقت
- **Rollback:** بازگشت به وضعیت پایدار قبل از گام خطا (در صورت پشتیبانی)
- **Compensation Action:** اجرای اقدامات جبرانی برای جبران اثر گام‌های قبلی در صورت شکست
- **Error Escalation:** ارجاع خطا به انسان یا تیم عملیات در صورت عدم امکان بازیابی خودکار
- **ثبت خطا:** ثبت کامل خطاها برای تحلیل و بهبود
- **Idempotency Check:** جلوگیری از اجرای مجدد عملیات در صورت دریافت درخواست یا رویداد تکراری
- **Dead Letter Handling:** انتقال درخواست‌های غیرقابل پردازش به صف خطا جهت بررسی بعدی

**الگوی Compensation (اقدام جبرانی):**

```text
Step 1: Create Issue (Jira)
        │
        ▼
Step 2: Assign to Developer
        │
        ▼
Step 3: Update Database
        │
        ▼
[ERROR] Step 3 Failed
        │
        ▼
Compensation Actions:
        │
        ├── Rollback Database Change
        │
        ├── Unassign Issue
        │
        └── Close Issue (or Mark as Failed)
        │
        ▼
Compensation Completed → Workflow Failed
```

### ۴.۷. Workflow Monitoring & Observability (پایش گردش‌کار)

**مسئولیت:** پایش وضعیت، پیشرفت و سلامت گردش‌کارها.

**متریک‌های کلیدی:**

| متریک                      | توضیح |
|:---------------------------| :--- |
| **Workflow Count**         | تعداد گردش‌کارهای فعال، تکمیل‌شده و ناموفق |
| **Step Count**             | تعداد گام‌های هر گردش‌کار |
| **Average Duration**       | میانگین زمان اجرای گردش‌کارها |
| **Success Rate**           | درصد گردش‌کارهای موفق |
| **Failure Rate**           | درصد گردش‌کارهای ناموفق با جزئیات نوع خطا |
| **Human Task Duration**    | میانگین زمان تکمیل Taskهای انسانی |
| **Retry Count**            | تعداد Retry در گام‌های مختلف |
| **Workflow SLA Violation** | تعداد گردش‌کارهایی که از زمان مجاز عبور کرده‌اند |
| **Queue Size**             | تعداد گردش‌کارهای در انتظار اجرا                 |
| **Average Wait Time**      | میانگین زمان انتظار در گام‌های انسانی یا رویدادی |
| **Execution Throughput**   | تعداد گردش‌کارهای تکمیل‌شده در واحد زمان         |


**داشبورد پیشنهادی:**

- **Overall Workflow Health:** وضعیت کلی گردش‌کارها
- **Running Workflows:** لیست گردش‌کارهای در حال اجرا با پیشرفت
- **Failed Workflows:** گردش‌کارهای ناموفق با جزئیات خطا
- **Human Tasks Pending:** Taskهای انسانی در انتظار پاسخ
- **Performance Trends:** روند عملکرد گردش‌کارها در طول زمان

## ۵. جریان کامل گردش‌کار

جریان کامل از شروع تا پایان یک گردش‌کار:

```text
Trigger (API, Event, Scheduled, Manual)
        │
        ▼
Workflow Instance Created
        │
        ├── Step 1: Execute (Automated / Agent / Human)
        │       │
        │       ├── Success → Continue
        │       │
        │       └── Failure → Retry / Rollback / Compensation
        │
        ├── Step 2: Execute
        │       │
        │       └── ...
        │
        ├── Decision Step (Conditional)
        │       │
        │       ├── Condition A → Path A
        │       │
        │       └── Condition B → Path B
        │
        ├── Parallel Execution
        │       │
        │       ├── Task A (Async)
        │       │
        │       ├── Task B (Async)
        │       │
        │       └── Wait for All
        │
        ├── Human Task (Approval / Input)
        │       │
        │       ├── Approved → Continue
        │       │
        │       ├── Rejected → Compensation / End
        │       │
        │       └── Timeout → Escalation / Auto‑Action
        │
        ▼
Workflow Completed / Failed / Canceled
        │
        ▼
Memory Update (Experience Store)
        │
        ▼
Events Published (WorkflowCompleted / WorkflowFailed)
```

## ۱۰. نتیجه‌گیری

دامنه **مدیریت جریان کار** به‌عنوان **هماهنگ‌کننده فرآیندهای سازمانی**، نقش حیاتی در خودکارسازی، مدیریت و پایش فرآیندهای چندمرحله‌ای کسب‌وکار ایفا می‌کند. معماری تعریف‌شده در این سند، چارچوبی استاندارد، انعطاف‌پذیر، مقیاس‌پذیر و قابل اعتماد برای تعریف، اجرا، پایش و مدیریت گردش‌کارهای پیچیده سازمانی فراهم می‌آورد.

رعایت اصول طراحی (Flexibility، Traceability، Fault Tolerance، State Management، Human‑in‑the‑Loop) و پیاده‌سازی مؤلفه‌های کلیدی (Workflow Definition، Workflow Engine، State Manager، Task Management، Human‑in‑the‑Loop، Error Handling) تضمین می‌کند که پلتفرم بتواند فرآیندهای سازمانی را به‌صورت خودکار، شفاف، قابل اعتماد و با قابلیت ممیزی کامل مدیریت کند و در عین حال با عامل‌ها و ابزارها به‌طور یکپارچه هماهنگ شود.

**مسئولیت به‌روزرسانی:** تیم معماری به همراه تیم‌های توسعه، محصول و عملیات مسئول بازبینی دوره‌ای این سند، به‌روزرسانی آن بر اساس تغییرات نیازمندی‌های گردش‌کار، الگوهای جدید فرآیندی و بازخورد تیم‌های پیاده‌سازی هستند.

**ثبات سند:** این سند باید با تغییرات در معماری کلان، نیازمندی‌های فرآیندهای کسب‌وکار و الزامات یکپارچه‌سازی هم‌گام باشد. هر تغییر در گردش‌کارها یا سیاست‌های اجرایی باید در این سند منعکس شود تا سایر اسناد معماری و طراحی نیز به‌روزرسانی شوند.
