**نام پلتفرم:** Enterprise AI Context & Automation Platform

**نسخه:** 1.1

**وضعیت:** پیش‌نویس بازبینی‌شده

**سند مرجع نام‌گذاری:** `Naming_And_Terminology_Glossary`

## ۱. هدف سند

این سند با هدف تعریف معماری دامنه یادگیری ماشین برای پلتفرم تدوین شده است. هدف آن ایجاد یک چارچوب استاندارد برای توسعه، آموزش، ارزیابی، استقرار، پایش و نگهداری مدل‌های یادگیری ماشین و هوش مصنوعی است تا تمامی قابلیت‌های هوشمند پلتفرم بر پایه فرآیندهای تکرارپذیر، مقیاس‌پذیر، قابل اعتماد و مسئولانه توسعه یابند.

این سند به‌عنوان مرجع اصلی برای تیم‌های علم داده، توسعه، معماری و عملیات در زمینه طراحی و پیاده‌سازی زیرساخت یادگیری ماشین پلتفرم عمل می‌کند.

## ۲. دامنه سند

این سند تمام جنبه‌های چرخه عمر یادگیری ماشین در پلتفرم را پوشش می‌دهد:

| حوزه | توضیح |
| :--- | :--- |
| **آزمایشگاه علم داده (Data Science Lab)** | محیط توسعه، آزمایش و اعتبارسنجی مدل‌ها شامل نوت‌بوک‌ها، داده‌ها و ابزارهای تحلیل |
| **مدیریت داده‌های آموزشی (Training Data Management)** | جمع‌آوری، پالایش، برچسب‌گذاری و نسخه‌بندی داده‌های مورد استفاده برای آموزش |
| **مخزن ویژگی‌ها (Feature Store)** | ذخیره، اشتراک و استفاده مجدد از ویژگی‌های مهندسی‌شده در آموزش و استنتاج |
| **آموزش مدل (Model Training)** | فرآیندهای آموزش، تنظیم ابرپارامتر (Hyperparameter Tuning) و بهینه‌سازی مدل‌ها |
| **ارزیابی مدل (Model Evaluation)** | اعتبارسنجی عملکرد، دقت، سوگیری و پایداری مدل‌ها |
| **ثبت نسخه مدل (Model Registry)** | نگهداری نسخه‌های مختلف مدل، وضعیت و Metadata مرتبط |
| **استقرار مدل (Model Deployment)** | قرار دادن مدل در محیط‌های مختلف برای ارائه سرویس |
| **پایش مدل (Model Monitoring)** | نظارت مستمر بر عملکرد، کیفیت و رفتار مدل در تولید |
| **بازآموزی و بازنشستگی (Retraining & Retirement)** | به‌روزرسانی یا حذف مدل‌ها بر اساس نیاز و عملکرد |
| **زیرساخت پردازش توزیع‌شده** | زیرساخت محاسباتی برای آموزش و استنتاج در مقیاس بزرگ |

## ۳. اهداف معماری

| هدف | توضیح |
| :--- | :--- |
| **استانداردسازی چرخه عمر مدل** | ایجاد فرآیندهای یکسان برای تمام مدل‌ها از توسعه تا بازنشستگی |
| **استفاده مجدد از ویژگی‌ها** | کاهش کار تکراری با ذخیره و اشتراک ویژگی‌های مهندسی‌شده بین تیم‌ها و پروژه‌ها |
| **کاهش زمان توسعه مدل** | خودکارسازی فرآیندهای تکراری و تسهیل آزمایش سریع |
| **استقرار ایمن و قابل تکرار** | تضمین اینکه استقرار مدل‌ها به‌صورت خودکار، قابل بازگشت و با حداقل ریسک انجام می‌شود |
| **پشتیبانی از مدل‌های سنتی و مدل‌های زبانی بزرگ** | توانایی پشتیبانی از طیف گسترده‌ای از مدل‌ها از رگرسیون ساده تا مدل‌های زبانی بزرگ |
| **مقیاس‌پذیری پردازش** | قابلیت افزایش منابع محاسباتی برای آموزش و استنتاج در حجم‌های بزرگ |

## ۴. اصول معماری

| اصل | توضیح |
| :--- | :--- |
| **مدل به‌عنوان محصول (Model as a Product)** | هر مدل به‌عنوان یک محصول مستقل با مالکیت، مستندات، سطح سرویس و چرخه عمر مشخص مدیریت می‌شود |
| **قابلیت بازتولید نتایج (Reproducibility)** | تمام فرآیندهای آموزش و ارزیابی باید قابل تکرار باشند و نتایج یکسانی در دفعات مختلف تولید کنند |
| **نسخه‌بندی (Versioning)** | تمام مدل‌ها، داده‌ها، ویژگی‌ها و کدها باید نسخه‌بندی شده و تغییرات آن‌ها قابل رهگیری باشد |
| **خودکارسازی (Automation First)** | هر فرآیندی که قابلیت خودکارسازی دارد باید خودکار شود تا خطا کاهش یابد و سرعت افزایش یابد |
| **هوش مصنوعی مسئولانه (Responsible AI)** | رعایت اصول عدالت، شفافیت، قابلیت تبیین، پاسخگویی و حریم خصوصی در تمام مراحل |
| **امنیت از ابتدای طراحی (Security by Design)** | کنترل‌های امنیتی در تمام مراحل چرخه عمر مدل از داده تا استقرار لحاظ می‌شوند |

## ۵. اجزای معماری (Architecture Components)

### ۵.۱. آزمایشگاه علم داده (Data Science Lab)

محیطی یکپارچه برای توسعه، آزمایش و اعتبارسنجی مدل‌ها:

| قابلیت | توضیح |
| :--- | :--- |
| **نوت‌بوک‌ها و محیط‌های توسعه یکپارچه (IDEs)** | محیط‌های تعاملی برای کدنویسی، آزمایش و بصری‌سازی داده (مانند Jupyter، VS Code) |
| **داده‌های نمونه** | دسترسی به داده‌های نمونه و تست برای توسعه اولیه |
| **ابزارهای تحلیل** | کتابخانه‌های آماری، بصری‌سازی و تحلیل داده |
| **محیط اجرای آزمایش‌ها** | امکان اجرای آزمایش‌های موازی و مقایسه نتایج |
| **کنترل نسخه** | یکپارچه‌سازی با Git برای مدیریت کد و نوت‌بوک‌ها |

---

### ۵.۲. مخزن ویژگی‌ها (Feature Store)

مخزن مرکزی برای ذخیره، اشتراک و استفاده مجدد از ویژگی‌های مهندسی‌شده:

| قابلیت | توضیح |
| :--- | :--- |
| **ثبت ویژگی (Feature Registration)** | ثبت ویژگی‌ها با Metadata شامل نام، نوع، منبع، توضیحات و مالک |
| **نسخه‌بندی ویژگی (Feature Versioning)** | نگهداری نسخه‌های مختلف ویژگی‌ها برای بازتولید و رهگیری تغییرات |
| **دسترسی یکپارچه (Unified Access)** | ارائه API یکسان برای دسترسی به ویژگی‌ها در آموزش و استنتاج |
| **پشتیبانی از دسته‌ای و بلادرنگ (Batch & Real-Time)** | ارائه ویژگی‌ها به‌صورت دسته‌ای (برای آموزش) و بلادرنگ (برای استنتاج) |
| **کیفیت و اعتبارسنجی** | بررسی کیفیت ویژگی‌ها و اعتبارسنجی آن‌ها پیش از استفاده |

---

### ۵.۳. ثبت آزمایش‌ها (Experiment Tracking)

ثبت و مدیریت تمام آزمایش‌های انجام‌شده:

| فیلد ثبت | توضیح |
| :--- | :--- |
| **پارامترها (Parameters)** | ابرپارامترها (Hyperparameters)، پیکربندی مدل و تنظیمات اجرا |
| **داده‌ها (Data)** | شناسه داده‌های آموزشی، ویژگی‌ها و نسخه آن‌ها |
| **نتایج (Results)** | معیارهای ارزیابی (دقت، F1، Loss و غیره) |
| **معیارهای کیفی (Quality Metrics)** | سوگیری، پایداری، زمان اجرا، مصرف منابع |
| **نسخه کد (Code Version)** | شناسه دقیق کد و نوت‌بوک استفاده‌شده |
| **زمان و محیط اجرا** | زمان اجرا، نوع سخت‌افزار، نسخه کتابخانه‌ها |

---

### ۵.۴. ثبت مدل (Model Registry)

مخزن مرکزی نسخه‌های مدل و اطلاعات مرتبط:

| فیلد | توضیح |
| :--- | :--- |
| **شناسه مدل (Model ID)** | شناسه یکتای مدل |
| **نسخه (Version)** | نسخه مدل با فرمت Semantic Versioning |
| **نوع مدل (Model Type)** | نوع مدل (مدل زبانی بزرگ، نمایش عددی، بازمرتب‌سازی، طبقه‌بندی، رگرسیون و غیره) |
| **وضعیت (Status)** | در حال توسعه، پیش‌تولید، تولید، منسوخ‌شده، بایگانی‌شده |
| **Metadata** | توضیحات، مالک، تاریخ ایجاد، وابستگی‌ها |
| **معیارهای عملکرد** | شاخص‌های ارزیابی و شرایط تأیید |
| **آرتیفکت‌ها (Artifacts)** | مسیر ذخیره‌سازی وزن‌ها، پیکربندی، نشانه‌گذار (Tokenizer) و فایل‌های مرتبط |
| **قابلیت‌های استنتاج** | نوع استنتاج (دسته‌ای، برخط)، محدودیت‌های ورودی/خروجی |

---

### ۵.۵. زیرساخت آموزش (Training Infrastructure)

زیرساخت اجرای آموزش مدل‌ها:

| قابلیت | توضیح |
| :--- | :--- |
| **پشتیبانی از CPU/GPU** | امکان استفاده از پردازنده‌های مختلف بر اساس نیاز مدل |
| **پردازش توزیع‌شده** | آموزش موازی روی چندین گره (Node) برای کاهش زمان |
| **زمان‌بندی Jobها (Scheduling)** | مدیریت صف و زمان‌بندی Jobهای آموزشی |
| **مدیریت منابع (Resource Management)** | تخصیص منابع بر اساس اولویت و نیاز |
| **پایش و لاگ‌گیری** | ثبت کامل فرآیند آموزش برای عیب‌یابی و تحلیل |

---

### ۵.۶. سرویس‌های استنتاج (Inference Services)

سرویس‌های ارائه پیش‌بینی یا پاسخ مدل به سایر سرویس‌های پلتفرم:

| قابلیت | توضیح |
| :--- | :--- |
| **استنتاج برخط (Online Inference)** | پاسخ‌دهی بلادرنگ با تأخیر کم برای سناریوهای تعاملی |
| **استنتاج دسته‌ای (Batch Inference)** | پردازش حجم‌های بزرگ داده در زمان‌های مشخص |
| **مقیاس‌پذیری خودکار** | افزایش/کاهش نمونه‌ها بر اساس بار |
| **بررسی سلامت و پایش (Health Check & Monitoring)** | بررسی سلامت و عملکرد سرویس |
| **بارگذاری و کش‌کردن (Loading & Caching)** | بارگذاری بهینه مدل و کش‌کردن نتایج پرتکرار |

## ۶. چرخه عمر مدل (Model Lifecycle)

مدل‌ها در پلتفرم از مراحل زیر عبور می‌کنند:

| مرحله | توضیح | خروجی |
| :--- | :--- | :--- |
| **۱. تعریف مسئله** | تعیین کاربرد، اهداف، معیارهای موفقیت و محدودیت‌های مدل | مستندات مسئله، معیارهای ارزیابی |
| **۲. آماده‌سازی داده** | جمع‌آوری، پالایش، برچسب‌گذاری، نرمال‌سازی و تقسیم داده | داده‌های آموزشی، اعتبارسنجی و تست |
| **۳. مهندسی ویژگی** | ایجاد، انتخاب و تبدیل ویژگی‌های مناسب | ویژگی‌های ثبت‌شده در Feature Store |
| **۴. آموزش** | اجرای فرآیند آموزش با تنظیم ابرپارامتر | مدل آموزش‌دیده، لاگ‌های آموزش |
| **۵. ارزیابی** | اعتبارسنجی عملکرد، دقت، سوگیری و پایداری | گزارش ارزیابی، تأیید یا رد مدل |
| **۶. ثبت مدل** | ذخیره مدل در Model Registry با Metadata کامل | نسخه ثبت‌شده در Model Registry |
| **۷. استقرار** | قرار دادن مدل در محیط تولید یا پیش‌تولید | سرویس استنتاج فعال |
| **۸. پایش** | نظارت مستمر بر عملکرد، کیفیت و رفتار | گزارش‌های پایش، هشدارها |
| **۹. بازآموزی/بازنشستگی** | به‌روزرسانی مدل یا حذف آن بر اساس نیاز | مدل جدید یا مدل بازنشسته |

---

## ۷. پردازش مقیاس‌پذیر (Scalable Processing)

معماری باید از قابلیت‌های زیر برای پردازش در مقیاس بزرگ پشتیبانی کند:

| قابلیت | توضیح |
| :--- | :--- |
| **پردازش موازی (Parallel Processing)** | اجرای هم‌زمان چندین Job آموزشی یا استنتاجی برای افزایش توان عملیاتی |
| **آموزش توزیع‌شده (Distributed Training)** | تقسیم بار آموزش بین چندین گره (هم‌راستایی داده، هم‌راستایی مدل) |
| **زمان‌بندی Jobها (Job Scheduling)** | مدیریت صف اولویت‌بندی‌شده و تخصیص منابع بر اساس نیاز |
| **شتاب‌دهنده‌های سخت‌افزاری** | استفاده از GPU، TPU و سایر شتاب‌دهنده‌ها برای مدل‌های سنگین |
| **استفاده از منابع ابری در صورت نیاز (Cloud Bursting)** | امکان استفاده از منابع ابری در صورت نیاز برای پردازش‌های سنگین |

---

## ۸. ارزیابی مدل (Model Evaluation)

شاخص‌های کلیدی ارزیابی مدل قبل از استقرار:

| شاخص | توضیح | اهمیت |
| :--- | :--- | :--- |
| **دقت (Accuracy)** | نسبت پیش‌بینی‌های صحیح به کل پیش‌بینی‌ها | بالا |
| **دقت مثبت (Precision)** | نسبت پیش‌بینی‌های مثبت صحیح به کل پیش‌بینی‌های مثبت | بالا |
| **نرخ بازیابی (Recall)** | نسبت پیش‌بینی‌های مثبت صحیح به کل موارد مثبت واقعی | بالا |
| **نمره F1 (F1 Score)** | میانگین هارمونیک Precision و Recall | بالا |
| **زمان پاسخ (Response Time)** | زمان مورد نیاز برای پردازش هر درخواست | بالا |
| **مصرف منابع (Resource Usage)** | مصرف CPU، حافظه و GPU در زمان اجرا | متوسط |
| **پایداری (Robustness)** | عملکرد مدل در برابر ورودی‌های غیرمنتظره و مرزی | بالا |
| **سوگیری (Bias)** | تبعیض ناعادلانه در خروجی بر اساس ویژگی‌های جمعیتی | بحرانی |

---

## ۹. استقرار مدل (Model Deployment)

استراتژی‌های استقرار مدل در محیط تولید:

| استراتژی | توضیح | کاربرد |
| :--- | :--- | :--- |
| **استنتاج دسته‌ای (Batch Inference)** | پردازش حجم‌های بزرگ داده در زمان‌های مشخص و ذخیره نتایج | گزارش‌های دوره‌ای، تحلیل‌های آفلاین |
| **استنتاج برخط (Online Inference)** | پاسخ‌دهی بلادرنگ با تأخیر کم (معمولاً < ۱۰۰ms) | تعاملات کاربری، Agentها، APIها |
| **آزمایش A/B (A/B Testing)** | هدایت درصدی از ترافیک به نسخه جدید و مقایسه عملکرد | ارزیابی عملکرد نسخه جدید با کاربران واقعی |
| **استقرار قناری (Canary Deployment)** | انتشار تدریجی نسخه جدید برای درصد کوچکی از کاربران و افزایش تدریجی | کاهش ریسک، شناسایی مشکلات زودهنگام |
| **استقرار آبی/سبز (Blue/Green Deployment)** | داشتن دو محیط کاملاً جداگانه و سوئیچ ترافیک پس از تأیید | عدم وقفه، بازگشت سریع |

---

## ۱۰. پایش مدل (Model Monitoring)

شاخص‌های کلیدی که برای مدل‌های در حال تولید پایش می‌شوند:

| شاخص | توضیح | فرکانس |
| :--- | :--- | :--- |
| **کیفیت مدل (Model Quality)** | دقت، F1 و سایر معیارهای اصلی | پیوسته / روزانه |
| **تغییر رفتار مدل (Drift)** | تغییر در توزیع ورودی‌ها (Data Drift) یا تغییر در رفتار مدل (Concept Drift) | روزانه / هفتگی |
| **نرخ خطا (Error Rate)** | درصد درخواست‌های ناموفق یا با خطای بالا | پیوسته |
| **تأخیر (Latency)** | زمان پاسخ مدل | پیوسته |
| **مصرف منابع** | مصرف CPU، حافظه، GPU و هزینه | پیوسته |
| **بازخورد کاربران** | امتیازات و نظرات کاربران درباره کیفیت پاسخ | روزانه / هفتگی |

**اقدامات در صورت مشاهده انحراف:**
- تولید هشدار برای تیم علم داده و عملیات
- بررسی علت (تغییر داده، افت کیفیت، خطای سرویس)
- در صورت لزوم، بازگشت به نسخه پایدار یا بازآموزی مدل

## ۱۱. امنیت (Security)

| کنترل | توضیح |
| :--- | :--- |
| **کنترل دسترسی به مدل‌ها** | مدیریت دسترسی به Model Registry بر اساس نقش (فقط خواندن، نوشتن، استقرار) |
| **محافظت از داده‌های آموزشی** | رمزنگاری و کنترل دسترسی به داده‌های آموزشی و ویژگی‌ها |
| **ثبت ممیزی (Audit Logging)** | ثبت تمام دسترسی‌ها، تغییرات و استقرارهای مدل برای رهگیری |
| **اعتبارسنجی داده‌های ورودی** | بررسی و پالایش ورودی‌های استنتاج برای جلوگیری از حملات |
| **محافظت در برابر حملات** | مقاوم‌سازی در برابر تزریق دستور، آلودگی داده، استخراج مدل و شکستن محدودیت‌ها |
